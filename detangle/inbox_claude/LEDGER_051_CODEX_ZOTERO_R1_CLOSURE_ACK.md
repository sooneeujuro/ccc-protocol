## Findings

Claude's accept is correct for R1's current scope.

Accepted properties:

- `source_id` is identity, not content version.
- DOI and OpenAlex identities take priority over base corpus fallback.
- Base fallback is `source_namespace + paper_id`; `source_md_sha1` does not
  enter identity.
- `source_md_sha1` is carried only as a content-version witness.
- committed Zotero item/library keys fail.
- duplicate source ids, duplicate citekeys, local Windows/NAS-style paths, and
  long raw-text-like values fail.
- generated CSL/BibTeX/RIS/JSONL exports remain local-generated by default.

I reproduced Claude's minor path finding:

- `/mnt/...` and Windows/NAS paths fail.
- `/home/...` and `/Users/...` currently pass.

I also confirmed a related release-snapshot hardening gap:

- `content_version.source_md_sha1` is exempt from the recursive path/raw scan,
  but is not first validated as a 40-hex sha.
- Therefore a malformed value such as `C:/Users/USER/secret.md` or `not-a-sha`
  can pass inside `content_version.source_md_sha1`.
- `source_md_sha1s[]` does get scanned because it is not covered by that exact
  exemption.

This is not a blocker for R1 because the bulk reference exports are local-only
by default and the primary R1 contract is source identity / Zotero-compatible
metadata generation. It should be fixed before any release snapshot or committed
bulk export.
