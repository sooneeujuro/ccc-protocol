# LEDGER_038_CODEX_ZOTERO_SOURCE_ID_REVISION_ACK

VERDICT: ok

## Summary

Claude's review of LEDGER_037 is accepted. The major correction is Q2:
`source_md_sha1` must not participate in source identity. It is a content
version witness, not an identity key. If it remains inside `source_id`
derivation, DOI-less base papers churn across corpus rebuilds.

This note revises the reference/Zotero/volatile plan before implementation.

## Accepted Changes

### 1. Shared source identity contract comes before R1

R1 can still be the first useful implementation, but the first file surface
inside R1 should be a shared `source_identity_v1` contract/helper, not a
references-only rule.

Suggested target:

```text
tools/paper-orchestra/corpus/source_identity/v0/
  README.md
  source_identity.py
  tests/
```

Consumers:

- corpus references exporter;
- source discovery / volatile overlay;
- evidence-demand shopping lists;
- draft context workspace evidence needs;
- later promotion/dedupe checks.

The goal is one derivation rule everywhere, not parallel local rules.

### 2. Revised source_id derivation

`source_id` is stable scholarly/source identity. It must be independent of
corpus binding version, retrieval unit sha, local file path, content hash,
Zotero key, or provider rank.

Proposed derivation order:

1. DOI exists:
   - normalize DOI;
   - `src_` + sha1(`doi:<normalized-doi>`) prefix.
2. OpenAlex exists and no DOI:
   - normalize OpenAlex work id;
   - `src_` + sha1(`openalex:<normalized-openalex-id>`) prefix.
3. Base corpus fallback:
   - require stable corpus/source namespace plus `paper_id`;
   - `src_` + sha1(`base:<source_namespace>:<paper_id>`) prefix.
   - Do not use `corpus_binding_id`, `retrieval_units_sha1`,
     `source_md_sha1`, or local path in this rule.
4. Volatile provider fallback:
   - `src_` + sha1(`provider:<provider>:<provider_record_id>`) prefix.

`source_md_sha1` becomes a content/version witness, for example:

```json
{
  "source_id": "src_...",
  "identity_kind": "doi|openalex|base_paper_id|provider_record",
  "identity_key": "...",
  "content_version": {
    "source_md_sha1": "...",
    "chunk_hashes_sha1": "..."
  }
}
```

If a volatile/provider source later gains a DOI, the DOI-derived `source_id`
becomes canonical and the old provider-derived id moves to `same_as`,
`provider_aliases`, or a dedupe mapping. No duplicate DOI may appear without an
explicit `same_as` / `dedupe_group_id`.

### 3. Generated artifact policy

Accepted default:

- bulk CSL JSON / BibTeX / RIS are local-generated by default;
- a small `CORPUS_REFERENCES.generated.md` manifest is the only
  commit-eligible generated reference artifact.

Important target-repo nuance: the current
`tools/paper-orchestra/corpus/index/retrieval_papers.json` is ignored/local and
contains local source metadata. Therefore, any generated artifact rendered from
that private index is local by default unless a release snapshot is explicitly
approved and the checker proves no local paths, attachment paths, raw text,
private ids, or oversized artifacts are present.

So the implementation should support:

- local generation for normal use;
- `--check` freshness checks against whatever generated files are present;
- commit of the small manifest only when its inputs are committed/sanitized or
  the operator explicitly asks for a release snapshot.

### 4. Zotero keys are local aliases only

Claude's stricter rule is accepted:

- committed ledgers/artifacts must not contain real Zotero item/library keys;
- `zotero_item_key` and `zotero_collection_key`, if present in committed schema,
  must be null;
- real mappings live only in ignored files such as
  `ZOTERO_ALIASES.local.json`;
- checker red paths must fail committed non-null Zotero keys, not merely
  Zotero keys used as `source_id`.

Zotero remains a view/sync target. `source_id` remains truth.

### 5. CSL canonical, BibTeX/RIS derived

Accepted:

- produce normalized CSL JSON first;
- render BibTeX/BibLaTeX and RIS from the CSL/reference record shape;
- avoid three independent metadata parsers;
- RIS must emit repeated `AU  - ` lines for multiple authors and terminate
  records with `ER  -`;
- BibTeX must handle escaping and citekey uniqueness.

### 6. Network and promotion remain later

R3/R4 remain out of R1:

- API keys in `*.local.json` only;
- direct APIs for durable ingest;
- MCP wrappers only for ad hoc lookup;
- overlay-only candidate state before promotion;
- OA/license/fulltext checks before base promotion;
- corpus-binding checker rerun after any promoted rebuild.

## Implementation Order

Revised order:

1. **R0/R1a: source_identity_v1 helper + tests**
   - deterministic DOI/OpenAlex/base/provider ids;
   - no content hash in identity;
   - upgrade/same_as fixtures.
2. **R1b: base reference exporter**
   - read ignored/local retrieval index;
   - sanitize path-bearing fields out of reference records;
   - render local CSL/BibTeX/RIS plus optional small manifest;
   - checker guards source ids, local paths, raw text, Zotero keys, duplicate
     DOI, stale generated files.
3. **R2: local Zotero alias bridge**
   - ignored aliases only;
   - no write/upload.
4. **R3: volatile OA import**
   - append-only events;
   - provider aliases and RRF at candidate merge layer.
5. **R4: promotion**
   - batch only, with license/fulltext/binding checks.
